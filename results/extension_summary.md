# Extension: the same mutation flow on two third-party designs

## Designs

| Design | Source | Licence | Files mutated | Configuration studied |
|---|---|---|---|---|
| Memory controller (this work) | `rtl/` | own | `mem_ctrl_fsm.v`, `cfg_regs.v`, `sync_mem.v`, `mem_ctrl_top.v` | DATA_W 8, ADDR_W 4 |
| Synchronous FIFO `sfifo` | ZipCPU wb2axip, commit 2e8d3bc | public domain | `sfifo.v` (formal section removed, RTL unchanged) | BW 8, LGFLEN 4, OPT_ASYNC_READ 0 |
| UART `uart_tx` + `uart_rx` + `uart` | alexforencich verilog-uart, commit 1b867e5 | MIT | `uart_tx.v`, `uart_rx.v`, `uart.v` | DATA_WIDTH 8, prescale 1 to 3 |

The third-party RTL is used as published. The testbenches, coverage monitors, formal properties, hand-written mutants and miters are new and were written for this study.

## Procedure (same as for the memory controller)

1. A self-checking testbench (v1) with a passive coverage monitor was written from the specification. It was run until every coverage bin was hit, then frozen (`designs/FROZEN_TB_V1.sha256`) before any mutant was run.
2. Hand-written semantic mutants (class DIR) were written from the specification before any run. Operator mutants were generated by the same rules as the memory controller (`mutation/oplib.py`; it reproduces all 149 memory controller mutants exactly).
3. Each mutant was run against v1, the formal property set (written once and not changed afterwards), a port-level miter, and, for miter-distinguishable survivors, a specification miter.
4. A testbench v2 was written to close the gaps shown by the non-equivalent survivors of v1.

Commands: `python3 mutation/flow.py <sfifo|uart> all`. Tools: Icarus Verilog 12.0, Yosys 0.33, SymbiYosys (yosys-0.33 tag), Yices 2.6.5.

|---|---|---|---|

| Equivalent | 13 | 9 (4 port, 4 unspecified output, 1 power-up) | 7 (4 port, 1 unspecified output, 2 argued) |
| Non-equivalent | 159 | 68 | 103 |
| Killed by simulation v1 | 154 (96.9 %) | 67 (98.5 %) | 83 (80.6 %) |
| Killed by simulation v2 | 159 (100 %) | 68 (100 %) | 103 (100 %) |
| Killed by formal properties | 153 (96.2 %) | 67 (98.5 %) | 81 (78.6 %) |
| Killed by formal but not by v1 | 1 | 0 | 9 |

| Killed by formal but not by v2 | 0 | 0 | 0 |
| Killed by v2 but not by formal | 6 | 1 | 22 |

Percentages are of the non-equivalent mutants. For the memory controller, v1 kills 154 of the 172 mutants; all 154 are non-equivalent.

Full coverage did not imply specification coverage in any of the three designs.

- **FIFO:** one gap, the power-up state. v1 always starts with a reset, but the design initialises its registers so that it can be used without one. Mutant G027 starts with the empty flag low. This is the same class of gap as the memory controller's power-up contents (D1b).
- **UART:** 20 real survivors, in five groups:
  - reset during a transfer: 11;
  - busy flags not checked: 4;
  - handshake timing of `s_axis_tready`: 3;
  - stop-bit length: 1;
  - false-start recovery: 1.

  v2 adds these checks and kills all 20.

## Simulation versus formal

On the memory controller, the first testbench missed one mutant that formal killed (G119), and the final testbench left formal with no extra kills. The size of the gap between the two methods depends on the design:

- On the FIFO, formal and v1 kill the same set of mutants.
- On the UART, formal kills 9 mutants that v1 misses (stop-bit length, `tready` behaviour, busy flags). v1 kills 11 that formal misses.
- Against v2, formal misses 22 non-equivalent UART mutants. All 22 trace to choices in the property set:
  - resets assumed only while the line is idle: 8;
  - no property on the busy flags while idle: 4;
  - no property on when an overrun is raised: 4;
  - a backpressure property with an exception wide enough to mask `m_axis_tready` faults: 3;
  - bit timing beyond the checked windows: 2;
  - false-start recovery: 1.

The formal properties have the same kind of specification gaps as the first testbench, and mutation exposes both.

## Observation on the UART transmitter

The formal properties showed a deviation from the AXI-Stream rule that a transfer happens only when `tvalid` and `tready` are both high. In the first idle cycle after reset, and after each frame when the next byte is already offered, `uart_tx` starts sending the byte while `s_axis_tready` is low. It raises `tready` one cycle later, inside the frame. With a master that keeps `tvalid` and the data stable until the handshake, as AXI-Stream requires, the byte is still sent correctly. The properties were written to accept this behaviour (`designs/uart/formal/formal_uart.sv`).

## Limits

- Equivalence is bounded:
  - FIFO: depth 24 at BW 2, LGFLEN 2;
  - UART: depth 80 at prescale 1 and at prescale 2, with DATA_WIDTH 2.
- An earlier UART run used depth 48. At that depth one mutant (G056) was wrongly classed as equivalent: it needs two received frames to show. Depth 80 covers two frames at prescale 1.
- The two argued UART mutants are judged by hand. With them counted as non-equivalent, the UART scores are 103 of 105 for v2 and 81 of 105 for formal.
- The same author wrote the testbench, the properties and the hand-written mutants. Freezing v1 before running any mutant limits, but does not remove, that bias.
- Formal runs that hit the time limit count as not killed, as in the memory controller flow. Two UART deep runs hit the limit while other jobs were running in parallel; both were rerun alone and passed. No timeouts remain.
